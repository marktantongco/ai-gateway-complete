User Guide

Project Introduction

BlacklistedAPI is an API proxy service that breaks through client limitations, converting free large models like Gemini, Antigravity, Qwen Code, Kiro that were originally only available within clients into standard OpenAI-compatible APIs that any application can call.

Unified Access

Access multiple large models with a single configuration through the standard OpenAI-compatible protocol

Break Through Limitations

Legitimately bypass free API rate and quota limits using OAuth authorization mechanism

Protocol Conversion

Supports intelligent conversion between OpenAI, Claude, and Gemini protocols

Account Pool Management

Supports multi-account round-robin, automatic failover, and configuration degradation

Client Configuration Guide

Below are configuration methods for common AI clients. Simply set the API endpoint to this service address:

Cherry Studio

  1. Open Settings → Model Service Provider
  2. Add custom service provider
  3. Set API address to: http://localhost:3000/{provider}/v1
  4. Enter API Key (REQUIRED_API_KEY from config file)

Cline / Continue

  1. Open VS Code Settings
  2. Search for Cline or Continue configuration
  3. Set API Base URL to: http://localhost:3000/{provider}/v1
  4. Enter API Key and model name

Generic cURL Call

curl http://localhost:3000/{provider}/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -d '{
    "model": "Model Name",
    "messages": [{"role": "user", "content": "Hello!"}],
    "max_tokens": 1000
  }'
Tip: Replace {provider} with the actual provider path, e.g. gemini-cli-oauth, claude-kiro-oauth. See the dashboard routing examples for complete paths.

FAQ

Q: What to do when request returns 404 Error?
A: Check if the API path is correct. Some clients automatically append paths to the base URL, causing path duplication. Check the actual request URL in the console and remove the extra path portion.
Q: What to do when request returns 429 Error?
A: 429 indicates too many requests. Configure multiple accounts in the provider pool and enable round-robin; or configure a fallback chain for cross-type degradation.
Q: What to do when OAuth Authorization Failed?
A: Ensure the OAuth callback port is accessible (Gemini: 8085, Antigravity: 8086, Kiro: 19876-19880). Docker users must ensure these ports are correctly mapped.
Q: What to do when streaming response is interrupted?
A: Check network stability, increase client request timeout. If using a proxy, ensure the proxy supports long connections.
Q: What to do when request returns "No available and healthy providers" Error?
A: This means all providers of the corresponding type are unavailable. Check provider health status on the "Provider Pool" page, confirm OAuth credentials have not expired, or configure a fallback chain for automatic failover to backup providers.
Q: What to do when request returns 403 Forbidden Error?
A: 403 indicates access denied. First check node status on the "Provider Pool" page. If node health check is normal, this error can be ignored. Other possible causes include: insufficient account permissions, restricted API key access, regional access restrictions, expired credentials, etc.
Q: Why should I enable "Enable OAuth Token Auto Refresh"?
A: OAuth tokens typically have a validity period (e.g., 1 hour). When enabled, the system automatically refreshes tokens about to expire in the background, ensuring 24/7 stable service and preventing request failures due to token expiration.
Q: What impact does not enabling "Pre-load Model Provider" have on token maintenance?
A: The system only performs automatic refresh for pre-loaded providers. If a provider is not pre-loaded, its tokens will not be automatically refreshed in the background, and prolonged disuse may cause token expiration. Add commonly used providers to the pre-load list.
